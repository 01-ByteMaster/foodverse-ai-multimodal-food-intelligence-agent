## Part 1. What you are building

FoodVerse AI is a full-stack, multimodal food intelligence platform.

| Layer | Technology | Role |
|---|---|---|
| Frontend | React 18 + Vite, custom neobrutalist CSS | Web app with five tools plus a home dashboard |
| Backend | FastAPI (Python) | API, validation, application logic |
| Vision | OpenCV (frames, colour analysis) + Gemini or Groq multimodal models | Recognise food, judge freshness, audit hygiene |
| Reasoning | Gemini or Groq LLM | Recipes, meal plans, insights |
| Storage | A small JSON file (`backend/data/history.json`) | Recent activity, no database needed |

Two operating modes, switchable at any time from the Settings button in the top bar:

- **Demo mode (no key).** Everything runs. Nutrition and hygiene return realistic sample results. Freshness uses a real OpenCV colour analysis. Recipes use a template. The meal planner uses real BMR/TDEE maths and a built-in meal library. This is perfect for first run, demos and offline development.
- **Live mode (Gemini or Groq key).** The photos and videos are analysed by a multimodal model and the recipes and plans are generated by an LLM.

Your API key is kept in the browser tab (session storage), sent with each request in a header, and never written to disk on the server. You can also set a server-wide key through environment variables.

Note on the stack: the master prompt mentions Streamlit, while the project requirements and architecture diagram specify React + FastAPI. This build follows the architecture diagram (React + FastAPI) and keeps the "zero external database, one-click deploy" goal by serving the compiled React app from the FastAPI process, so one container is the whole product.

## Part 2. Install the prerequisites

You need Python 3.9 or newer (3.11 recommended), Node.js 18 or newer (20 recommended), and Git.

Check what you already have:

```bash
python --version      # or python3 --version
node --version
npm --version
git --version
```

If something is missing:

- **Windows 10/11:** install Python from python.org (tick "Add python.exe to PATH"), Node.js LTS from nodejs.org, and Git from git-scm.com.
- **macOS:** `brew install python node git` (or use the installers above).
- **Ubuntu 20.04+:** `sudo apt update && sudo apt install -y python3 python3-venv python3-pip nodejs npm git`. If your `node --version` is below 18, install a newer Node from nodejs.org or with nvm.

Recommended editor: Visual Studio Code.

## Part 3. Get a free AI key (optional)

Skip this part if you only want demo mode. You can add a key later.

**Google Gemini (recommended, handles images and video frames well)**

1. Open Google AI Studio (aistudio.google.com) and sign in.
2. Choose "Get API key", then create a key.
3. Copy it. Treat it like a password.

**Groq (fast Llama models)**

1. Open console.groq.com and sign in.
2. Go to API Keys, create a key, and copy it.

Free-tier limits and model names change over time. If a request fails with a "model not found" message, set a current model name in `backend/.env`. The defaults are in `.env.example`:

```
GEMINI_MODEL=gemini-2.5-flash
GROQ_VISION_MODEL=meta-llama/llama-4-scout-17b-16e-instruct
GROQ_TEXT_MODEL=llama-3.3-70b-versatile
```

Check the provider's model list for the current names.

## Part 4. Run it locally (development)

Open the project folder in a terminal. You will use two terminals: one for the backend, one for the frontend.

### Terminal 1: backend

```bash
cd backend

# create and activate a virtual environment
python -m venv .venv
source .venv/bin/activate          # macOS / Linux
# .venv\Scripts\activate           # Windows (cmd or PowerShell)

pip install -r requirements.txt

# optional: server-side keys (the backend loads backend/.env automatically)
cp .env.example .env               # Windows: copy .env.example .env
# then edit .env and fill in GEMINI_API_KEY or GROQ_API_KEY

uvicorn main:app --reload --port 8000
```

You should see `Uvicorn running on http://127.0.0.1:8000`. Visit http://localhost:8000/api/health. You should get `{"status":"ok","mode":"demo",...}`. Interactive API docs are at http://localhost:8000/docs.

Note on `.env`: it is optional. Without it the app runs in demo mode and each user can paste their own key in the web app's Settings dialog. Keys typed in the web app override the server key.

### Terminal 2: frontend

```bash
cd frontend
npm install
npm run dev
```

Open http://localhost:5173. Vite proxies every `/api` request to the backend on port 8000, so there are no CORS problems.

### Add your key in the app

1. Click the **Demo mode - Settings** button in the top bar.
2. Choose Gemini or Groq, paste the key, press **Save settings**.
3. The button turns green and reads **Live AI**.

To go back to demo mode, open Settings and press **Switch to demo mode**.

### Run the production build locally (what the deployed app does)

```bash
cd frontend && npm run build        # creates frontend/dist
cd ../backend && uvicorn main:app --port 8000
```

Now http://localhost:8000 serves the complete app (UI and API from one process).

## Part 5. Test every feature

Use any real photos. Good test inputs: a plate of food, a spotted banana and a fresh one, a photo or short clip of a kitchen.

**1. Nutrition (Epic 2).** Open Nutrition, upload a meal photo, press **Analyse this meal**. Expect the dish name, cuisine, portion, a health score ring, calories, protein/carbs/fat/fibre/sugar/sodium bars, a macro donut, ingredients, allergen alerts, insights and healthier suggestions.

**2. Freshness (Epic 3).** Open Freshness, upload a produce or meat photo, optionally type what it is, press **Check freshness**. Expect a stage (Fresh, Moderately Fresh or Spoiled), a score, a verdict (Safe to consume, Consume within 24h, Discard immediately), observations, storage tips and the OpenCV measurements.

**3. Hygiene (Epic 4).** Open Hygiene, upload a kitchen image or an MP4/MOV clip (up to 40 MB). Videos are sampled into 5 frames. Expect a compliance percentage, a rating, a six-item checklist (hair cap, gloves, sanitisation, cross-contamination, food handling, cleanliness) and a violation log with severity and fixes. The score is calculated by the server from the checklist: passes divided by judged items.

**4. Recipes (Epic 4).** Open Recipes, type `eggs, spinach, rice` and press Add (or Enter), choose diet, time and servings, press **Get recipes**. Expect recipe cards with time, difficulty, calories, ingredients (have or need), steps, swaps and a chef tip.

**5. Meal planner (Epic 5).** Open Planner, fill in the profile, press **Build my 7-day plan**. Expect BMR, TDEE, BMI, a daily calorie target with macro bars, Monday to Sunday tabs with four meals each, and a grocery list grouped by aisle with tick boxes and a Print button.

**6. History.** Return to Home. The Recent activity card lists your last analyses. **Clear** empties it.

**7. Edge cases (Epic 6).** Try these and confirm you get a clear message, not a crash:

- Upload a `.txt` file renamed to `.jpg`: friendly error.
- Press Analyse with a very large image (over 8 MB): "File too large".
- Stop the backend and press Analyse: "Cannot reach the FoodVerse server...".
- Enter a wrong API key: "API key rejected or request invalid".
- Resize the browser to phone width: the layout becomes a single column and the navigation scrolls sideways.
- Press Tab repeatedly: every control shows a visible focus outline.

## Part 7. Deploy

Pick one route. Route A is the easiest and recommended.

First, put the project on GitHub:

```bash
cd foodverse
git init
git add .
git commit -m "FoodVerse AI"
# create an empty repository on github.com, then:
git branch -M main
git remote add origin https://github.com/YOUR-USER/foodverse.git
git push -u origin main
```

`.gitignore` already excludes `node_modules`, `dist`, virtual environments, `.env` and the history file, so no secrets are committed.

### Route A: one service on Render (UI + API together)

The included `Dockerfile` builds the React app and serves it from FastAPI, so a single web service is the whole product.

1. Create an account at render.com and connect your GitHub.
2. Choose **New**, then **Blueprint**, select your repository. Render reads `render.yaml`.
   (Or choose **New**, **Web Service**, pick the repo, and set Runtime to **Docker**.)
3. When prompted, you may add `GEMINI_API_KEY` or `GROQ_API_KEY`. Leave them empty to deploy in demo mode, and let visitors paste their own key in the app.
4. Press deploy and wait for the build (a few minutes the first time).
5. Open the URL Render gives you. Check `https://YOUR-APP.onrender.com/api/health`.

Things to know about free hosting:

- Free services usually sleep after inactivity, so the first request can take a while.
- The disk is ephemeral, so Recent activity resets on redeploy. That is expected with the no-database design. For permanent history, replace `services/store.py` with SQLite on a persistent disk or a hosted database.
- Video analysis needs memory. If large clips fail on a small instance, reduce the clip length or move to a larger instance.

### Route B: split deploy (frontend on a static host, backend elsewhere)

Use this if you want the UI on Vercel or Netlify.

1. Deploy the backend as in Route A (or any host that runs the Dockerfile).
2. On the backend, set `CORS_ORIGINS=https://your-frontend-domain` so the browser is allowed to call it.
3. On the static host, import the repo, set the root directory to `frontend`, build command `npm run build`, output directory `dist`.
4. Add the environment variable `VITE_API_URL=https://your-backend-domain` (no trailing slash) before building.
5. Redeploy and open the frontend URL.

### Route C: AWS (you have AWS CLI in the requirements)

The same Docker image runs on AWS. One straightforward path is AWS App Runner:

```bash
aws configure                                   # once: access key, secret, region
aws ecr create-repository --repository-name foodverse-ai
aws ecr get-login-password | docker login --username AWS --password-stdin ACCOUNT_ID.dkr.ecr.REGION.amazonaws.com
docker build -t foodverse-ai .
docker tag foodverse-ai:latest ACCOUNT_ID.dkr.ecr.REGION.amazonaws.com/foodverse-ai:latest
docker push ACCOUNT_ID.dkr.ecr.REGION.amazonaws.com/foodverse-ai:latest
```

Then in the AWS console open App Runner, create a service from the ECR image, set port `8000`, add `GEMINI_API_KEY` as a secret environment variable, and use `/api/health` as the health check path. An EC2 instance with Docker (`docker run -p 80:8000 foodverse-ai`) also works. Replace `ACCOUNT_ID` and `REGION` with your values.

### Run the container locally before deploying

```bash
docker build -t foodverse-ai .
docker run --rm -p 8000:8000 -e GEMINI_API_KEY=your_key foodverse-ai
# open http://localhost:8000
```

### Post-deploy checklist

- `/api/health` returns `status: ok`.
- The home page loads and the navigation works.
- Run one analysis in each tool.
- Open Settings, add a key, and confirm the badge turns to **Live AI**.
- Never commit a real key. Rotate any key that was ever pasted into a public place.

## Part 8. API reference

All routes are under `/api`. Optional headers on every call: `X-Provider` (`gemini` or `groq`) and `X-API-Key`. With no key, the server answers in demo mode and each response includes `"mode": "demo"` or `"live"`.

| Method | Path | Body | Returns |
|---|---|---|---|
| GET | `/api/health` | none | `{status, mode, provider}` |
| POST | `/api/nutrition` | multipart `file` (image, 8 MB max) | dish, cuisine, portion, ingredients, nutrition, allergens, health score, insights, suggestions |
| POST | `/api/freshness` | multipart `file` (image), optional `item` | stage, freshness score, observations, verdict, storage tips, shelf life, OpenCV metrics |
| POST | `/api/hygiene` | multipart `file` (image or video, 40 MB max) | compliance score, rating, indicators, violations, summary, frames analysed |
| POST | `/api/recipes` | JSON `{ingredients[], diet, max_minutes, servings}` | recipes with steps, swaps and nutrition |
| POST | `/api/mealplan` | JSON profile (age, gender, weight_kg, height_cm, activity, goal, diet, allergies) | targets (BMR, TDEE, calories, macros, BMI), 7 days of meals, grocery list |
| GET | `/api/history` | none | last 50 analyses |
| DELETE | `/api/history` | none | clears history |

Errors use standard codes with a readable `detail`: 415 wrong file type, 413 too large, 422 invalid input, 502 AI provider problem.

The calorie maths in the planner:

- BMR (Mifflin-St Jeor): `10 x kg + 6.25 x cm - 5 x age + 5` for men, `... - 161` for women.
- TDEE: BMR multiplied by an activity factor (1.2 sedentary up to 1.9 athlete).
- Goal: fat loss subtracts 20%, muscle gain adds 10%. Calories never go below 1,200 (women) or 1,500 (men).
- Macro split depends on the diet (for example keto is 70% fat) with a small protein bonus for fat loss and muscle gain.

## Part 9. How the code works and how to extend it

**Request flow.** A page in `frontend/src/pages` calls a function in `api.js`, which adds the provider and key headers and posts to FastAPI. A route in `main.py` validates the upload (type, size), calls a service in `backend/services`, writes a history entry, and returns JSON. The service builds a strict prompt that demands JSON in a fixed shape, calls `llm.ask_json`, then normalises the result (clamping scores, filling defaults) so the UI never receives a surprise shape.

**Why scores are computed in code where possible.** The hygiene score is derived from the checklist, the planner targets come from formulas, and the health score is clamped to 1 to 100. This keeps the numbers consistent and explainable rather than relying on the model to do arithmetic.

**Add a new tool, for example a "Leftover safety" checker:**

1. Create `backend/services/leftovers.py` with a prompt, a demo fallback and an `analyze` function.
2. Add a route in `main.py` that validates input, calls it through `guarded(...)`, and calls `store.add(...)`.
3. Add a method in `frontend/src/api.js`, a page in `frontend/src/pages`, and a line in the `TABS` list in `App.jsx`.
4. Add a test in `backend/tests/test_api.py`.

**Change the look.** All colours are CSS variables at the top of `frontend/src/styles.css` (`--lemon`, `--mint`, `--sky`, `--tomato`, `--grape`, `--bw` for border width, `--shadow` for the hard shadow). Change them and everything follows.

**Switch models.** Set `GEMINI_MODEL`, `GROQ_VISION_MODEL` or `GROQ_TEXT_MODEL` as environment variables. No code change is needed.

**Privacy and safety notes.**

- Uploaded files are processed in memory (videos use a temporary file that is deleted immediately) and are not stored.
- Results are estimates. Calories are approximations from a photo. Freshness and hygiene are aids, not lab tests or official inspections. The footer says so. For freshness the guidance is always: when in doubt, throw it out.

## Part 10. Troubleshooting

| Symptom | Fix |
|---|---|
| `python` not found | Use `python3`, or reinstall Python with "Add to PATH" ticked |
| `pip install` fails on opencv | Upgrade pip (`python -m pip install -U pip`) and confirm Python is 3.9 to 3.12 |
| PowerShell blocks `activate` | Run `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once, then retry |
| Top bar says **Server offline** | The backend is not running on port 8000. Start it in Terminal 1 |
| Port 8000 already in use | Start with `--port 8001` and change the proxy target in `frontend/vite.config.js` |
| Browser shows CORS errors (split deploy) | Set `CORS_ORIGINS` on the backend to your exact frontend URL, no trailing slash |
| "API key rejected or request invalid" | Re-copy the key, check the provider selected in Settings matches the key, and check the model name |
| "model not found" style errors | The provider retired a model. Set a current model name in the environment variables |
| "Rate limit reached" | Wait a minute, or use another provider or key |
| Video upload fails | Use MP4 or MOV, under 40 MB, and a short clip. Re-encode if the codec is unusual |
| Results say "Demo mode" | No key was found. Add one in Settings, then run the analysis again |
| `npm run build` fails | Delete `frontend/node_modules`, run `npm install` again, and confirm Node is 18 or newer |
| Deployed app is blank | Check the build logs. The Docker build must finish the `npm run build` step. Visit `/api/health` to confirm the API |
| Fonts look plain | The Google Fonts link needs internet. The design falls back to Arial Black and system fonts offline |
